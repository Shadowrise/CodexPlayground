# Исследование FPS у качелей, 23 октября 2026

Открыть `report.html` через локальный Vite-сервер. Он содержит интерактивные
диаграммы, сравнение ракурсов, времён суток, методику и ссылки на сырые данные.
`summary.json` — производные показатели; `report-*.json` — три завершённых
запуска. `preliminary-incomplete.json` сохранён для диагностики и не входит
в итоговые расчёты.

Проверена отдельная аппаратная сессия Chrome 156, RTX 3060 Laptop, окно
1920×1080, рендер 2400×1350, дальность 360 м. Персонаж сидит на настоящих
качелях; живые замеры включают симуляцию и вращение камеры. A/B замораживают
сцену. Основные кандидаты проверены 114 короткими парными сравнениями в
перемешанном порядке, в трёх направлениях камеры. В 107 сравнениях исходный
и повторный контроль расходились не более чем на 15%.

Выигрыш от временного исключения группы — верхняя оценка её вклада, а не
обещание такого же ускорения после оптимизации. Значения не складываются.
Сессия Chrome, расположение NPC, версия рабочих файлов и общая нагрузка GPU
могут различаться между запусками. Сопоставлять напрямую абсолютный FPS
разных запусков нельзя. Главные выводы опираются на сравнения внутри одной
замороженной сцены. Игровая логика занимала около 2–3 мс, основной расход
приходился на render() и обработку отправленных команд GPU.

Первый приоритет: дальняя детализация и объединение частей светлячков,
упрощённые теневые модели персонажей, сокращение обходов/обновлений карт.
Лес и масштаб рендера помогают в зависимости от ракурса. Само игровое утро
не показало устойчивой большой разницы относительно полудня при фиксированной
камере; часть временных сравнений остаётся шумной.

Повторить на запущенной локальной игре из `kirby-game`:

```powershell
$env:GAME_URL='http://127.0.0.1:5183/'
node scripts/research-scene-performance.mjs
$env:PERF_RESEARCH_MODE='focused'
$env:PERF_ANGLES='45,135,225'
$env:PERF_ROUNDS='4'
node scripts/research-scene-performance.mjs
node scripts/summarize-scene-performance.mjs
node scripts/create-scene-performance-report.mjs
```

Исследовательский скрипт использует отдельный Chrome. Во время GPU-замеров
лучше не создавать дополнительную меняющуюся нагрузку в других игровых
окнах. Перед измерениями прогреваются ракурсы. GPU измеряется через
`EXT_disjoint_timer_query_webgl2`, а частоты и температура — через
`nvidia-smi`, если утилита установлена. В сырых данных отдельно сохранён
стартовый GL-флаг; в коротких измеряемых сравнениях ошибок WebGL не было.

В первоначальных данных `renderer.info` не учитывал CSM-вызовы у двух
вариантов, обходящих GroundShadowPass: Three сбрасывал счётчик после теней.
В сводке число пропущенных вызовов восстановлено из варианта `csm-update`
той же замороженной сцены и ракурса. Время CPU/GPU это не меняет. В текущем
исследовательском скрипте перед каждым кадром применяется явный сброс
счётчиков, поэтому будущие запуски сразу включают все проходы.
